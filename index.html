kd3

Embeddable & offloadable. High-performance static kd-trees.

kd3 indexes points for nearest-neighbour queries, k-NN, rays, and predicate-filtered searches. Construction runs in parallel, queries use bounded stack space and caller-provided buffers, and the payload is application-defined.

Try the demosSee benchmarks
Embedded first

No exceptions, no RTTI, bounded query stack, and no allocation during queries.

Parallel construction

OpenMP task-based building for large point sets.

Low-dimensional

Designed for 2D to 4D keys, with support for higher dimensions.

Header-only

Drop include/kd3/ into your project. No required runtime.

C interface

A stb-style C wrapper for FFI and non-C++ callers.

GLSL generator

Generate shader query functions for the 2D to 4D tree layouts.

Comparison with nanoflann

kd3 targets static low-dimensional point clouds. nanoflann covers a broader feature set. The full matrix is on the comparison page.

kd3 is stronger for

  • Static 2D-4D clouds, near-data queries, and AABB pruning.
  • Built-in filtered, ray, and cylinder queries.
  • Caller-owned k-NN buffers and a trivially copyable view.
  • C API, GLSL generator, and header-only C++23.

nanoflann is stronger for

  • Radius, approximate, and custom-metric search.
  • Dynamic, incremental, and runtime-dimensional indexes.
  • Non-owning adaptors and built-in index serialization.
  • C++11, no OpenMP requirement, and a permissive licence.

Balanced tree, flat storage, explicit queries

kd3 builds a balanced binary tree over fixed-size leaf buckets. The payload is application-defined.

Split on the widest axis

The builder computes tight bounds for each subtree, splits along the widest axis at the median, and recurses until each leaf holds at mostleaf_size points. Leaves are packed into fixed-size buckets; empty slots are padded with INF andINF_IDX.

Each split removes half the remaining points from consideration. The leaves are the only place where full point coordinates are stored.

Four flat arrays

For N = 7000, leaf_size = 8, andD = 3, the tree has B = 875 leaf buckets. The owning KdTree holds four contiguous arrays; the non-owning KdTreeView is just spans into them plus the root bounds.

Build from runtime data, then query

The tree is constructed from a mutable span of points. It sorts the input, owns the resulting arrays, and returns anstd::expected. Rebuild after data changes; the query view itself stays trivially copyable.

From your own container

Build takes a mutable span of FatPoint. It partitions the data in place and allocates the final tree storage up front.

using Tree = kd3::KdTree<kd3::limits<float, 3>>;
std::vector<Tree::FatPoint> points;

for (const auto& sample : samples) {
    points.push_back({sample.position, sample.id});
}

auto tree = Tree::build(points);
if (!tree) return false;

auto hit = tree->query_1nn(target);

Scalar, dimension, distance, payload

limits controls all four. Higher-dimensional keys work for position plus normal. Integer scalars and wider distance accumulators are supported.

using Point2 = kd3::KdTree<kd3::limits<float, 2>>;
using Fixed5 = kd3::KdTree<
    kd3::limits<std::int16_t, 5, std::int64_t, std::uint32_t>
>;
using Oriented = kd3::KdTree<kd3::limits<float, 6>>;

Same index, different answers

Queries return std::expected. k-NN writes into a caller buffer. Filtered queries take a predicate and never update the bound for rejected points.

auto nearest = tree->query_1nn(target);

std::array<Tree::KnnResult, 8> buffer;
auto nearest8 = tree->query_knn(target, buffer);

auto valid = tree->query_1nn_if(
    target,
    [&](std::uint32_t id, const auto&) {
        return enabled[id];
    });

STB-style wrapper for FFI

Define KD3_CXX_IMPL once, include the C header elsewhere. It exposes create, destroy, 1-NN, k-NN, distance, and ray queries. Filtered queries remain C++ only for now.

#define KD3_CXX_IMPL
#include <kd3/kd3-c.h>

kd3_tree_t* tree = kd3_tree_create(points, n, &err);
kd3_knn_result_t hit;
kd3_tree_query_1nn(tree, target, &hit);
kd3_tree_destroy(tree);

Query functions for the GPU

Generates 1-NN, k-NN, and ray query functions for 2D to 4D trees. The generated code uses the same split and bucket layout as the CPU tree.

auto glsl = kd3::generate_glsl<
    kd3::limits<float>,
    Tree::cfg,
    {.binding_vals = 1, .binding_dims = 2,
     .binding_bks = 3, .binding_boxes = 4}
>();

Rebuild, do not mutate the view

The core tree is immutable. Rebuild after data changes, or use the example mutable wrapper. Keeping construction separate is what makes the view trivially copyable.

// After points change:
auto rebuilt = Tree::build(points);
if (rebuilt) tree = std::move(*rebuilt);

// Or see examples/mutable/mut.hpp.
